# Eagle Eye — AI Vision for Cabinet QC

Eagle Eye is a **proposed** AI-assisted inspection workflow for electrical / industrial control cabinets. An inspector uploads cabinet photos and engineering documents; the system extracts what *should* be in the cabinet, detects what is *visibly* there, compares the two with deterministic rules, and returns `PASS`, `FAIL` or `REVIEW` for each check, with image evidence. A human inspector makes the final call.

> **Status: documentation + scaffold only.** The inspection workflow is **not implemented**. No model has been trained. See [Feature status](#feature-status). This project is not an industrially certified inspection product.

## Problem and proposed solution
Manual cabinet QC means comparing photos against drawings, component lists and labels. It is slow, hard to standardise, and leaves weak evidence trails. Eagle Eye proposes a structured, evidence-based digital workflow (see [PRD.md](PRD.md), [SYSTEM_WORKFLOW.md](SYSTEM_WORKFLOW.md)).

**Key principle:** YOLO is *one component*, not the whole system. Detection, OCR, document parsing, matching, rules and human review are separate stages ([ARCHITECTURE.md](ARCHITECTURE.md)). When evidence is insufficient the answer is `REVIEW`, never a guessed pass/fail.

## Key capabilities (planned)
Inspection creation and history · image + CSV/XLSX/PDF upload · expected-item extraction · YOLO detection · OCR · expected-vs-observed matching · rule engine · evidence with bounding boxes · inspector review · PDF report.

## Architecture overview
React/TypeScript UI → FastAPI → services → (parsers, vision, OCR, matching, checks, reporting) → SQLite + file storage. Model weights are loaded from `models/custom/best.pt` with a `model_manifest.json`. Diagrams: [docs/diagrams/](docs/diagrams/).

## Technology stack
React, TypeScript, Vite, Tailwind CSS · Python, FastAPI, Pydantic, SQLAlchemy, SQLite · Ultralytics YOLO, OpenCV, EasyOCR (baseline) · PyMuPDF, pandas, openpyxl · ReportLab · pytest, Ruff. Details and alternatives: [TECH_STACK.md](TECH_STACK.md).

## Prerequisites
Python 3.10+ (3.11 recommended), Node.js 20 LTS, Git. A GPU is needed only for training (use Google Colab). See [INSTALLATION.md](INSTALLATION.md).

## Quick start (Windows PowerShell)
```powershell
python -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
Copy-Item .env.example .env
uvicorn app.main:app --reload --app-dir backend      # terminal 1 -> http://127.0.0.1:8000/docs
cd frontend; npm install; npm run dev                # terminal 2 -> http://localhost:5173
```
Health check: `curl http://127.0.0.1:8000/api/health`. API docs (auto-generated by FastAPI): `/docs`. Planned contract: [API.md](API.md).

## Dataset and model setup
Plan: **public datasets only** (no own data collection). Pick one colour-photo dataset after checking its images (note: `hi-wxre3` is thermal and unsuitable); candidates, the image check, folder placement (`data/raw/<name>/`) and license cautions are in [DATASET.md](DATASET.md). What to feed the app: [DEMO_INPUTS.md](DEMO_INPUTS.md). Then follow [MODEL_TRAINING.md](MODEL_TRAINING.md). Colab overview: train in Colab → download `best.pt` → place in `models/custom/` → fill in the manifest. Without a model the backend reports `model_file_found: false`.

## Known limitations
Photos cannot reliably prove wiring correctness; non-detection is not proof of absence; PDF parsing is best-effort for text-based PDFs only; no authentication in the MVP. See [ARCHITECTURE.md](ARCHITECTURE.md#13-known-limitations) and [RISK_REGISTER.md](RISK_REGISTER.md).
